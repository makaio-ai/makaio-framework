Make the execution attempt boundary generic over the owner's outcome type (#1262). `ExecutionAttemptRepository<TOutcome>`, `ExecutionAttemptAuthority<TOutcome>`, `ExecutionAttemptOutcomeCommit<TOutcome>`, `ExecutionAttemptOutcomeDecision<TOutcome>`, and `AuthorityDispatchRunnerOptions<TOutcome>` take a required type parameter with no default; the workflow engine binds them to `WorkflowRunResult`. New exports from `@makaio/subsystem-workflow-engine`: `ExecutionOwnerId`, `OutcomeCodec`, `OutcomeConvergence`, `OutcomeConvergenceInput`, `OutcomePreCommitValidation`, and `submitAttemptOutcome`, the lifted validate → commit → converge → settle invariant that the `worker.control.outcome.submit` handler now delegates to. `OutcomeConvergence.converge` takes the named `OutcomeConvergenceInput<TOutcome>` rather than an inline shape.

Breaking:

- `sameWorkflowResult` is replaced by `sameDurableOutcome(stored, candidate)`, which compares two codec-produced durable texts: the one the attempt stored and the one the submission would store. Equality is therefore decided over what an attempt actually holds, so a codec that normalizes while serializing — or encodes a value JSON has no form of its own for — yields the same decision in every realization, and a retry is never compared against a re-serialization of the already-normalized value. An accepted commit reports what the stored text reads back as rather than the submitter's copy.
- The port renders a submission exactly once. `ExecutionAttemptRepository<T>` gains `canonicalizeOutcome(outcome: T): DurableOutcome<T>` — the text a commit would persist together with the outcome that text yields — and `ExecutionAttemptOutcomeCommit<T>.result` is that `DurableOutcome<T>` rather than a raw `T`; `ExecutionAttemptAuthority<T>` exposes `canonicalizeOutcome` and takes the rendering in `commitOutcome`. A realization stores `result.text` verbatim and never re-serializes. `submitAttemptOutcome` renders once, validates `durable.outcome`, and commits `durable`, so the submitter's object is read once and neither a second serialization nor a mutation of that object while an await is pending can make the committed outcome differ from the validated one. New exports from `@makaio/subsystem-workflow-engine`: the `DurableOutcome` type and the `durableOutcome(codec, outcome)` rendering rule every realization owes; `DurableOutcome` is no longer exported from the `/testing` entry. Every repository realization and every `commitOutcome` caller must be updated.
- `ExecutionAttemptRepository<T>` gains `decodeOutcome(text: string): T` — the read rule every realization owes, stated once as the exported `decodeDurableOutcome(codec, text)` — and `ExecutionAttemptAuthority<T>` exposes it. The durable text is the only copy of an outcome no caller has touched: an `accepted` decision now reports `decodeOutcome(result.text)` rather than `result.outcome`, which the caller held across its own pre-commit validation and may have mutated there, and `submitAttemptOutcome` settles the waiter from a fresh decode of the durable text rather than from the decision object it just handed to convergence. Every repository realization must implement `decodeOutcome`.
- The settling variants of `ExecutionAttemptOutcomeDecision<T>` carry the durable text alongside the outcome: `{ kind: 'accepted' | 'duplicate'; outcome: T; text: string }`. It is the text the attempt holds — `result.text` for `accepted`, and the *stored* text for `duplicate`, not the retry's own rendering, since `sameDurableOutcome` judges two texts the same outcome while their member order still differs. `submitAttemptOutcome` settles the waiter from `decodeOutcome(decision.text)`, so an equivalent retry resolves the runner with the committed representation rather than its own. Every repository realization must report `text` on both settling decisions.
- `OutcomeCodec`'s durable text must be strict JSON in the sense `JSON.stringify` defines: finite numbers only. Non-finite numbers — `Infinity`, `-Infinity`, `NaN`, however spelled — and anything else JSON has no form for are outside the contract, because `sameDurableOutcome` canonicalizes the parsed text and renders every such value as `null`. A codec whose outcomes need them encodes them as values JSON does have.
- `OutcomeCodec.parse` and `OutcomeCodec.serialize` must be deterministic, pure functions of their argument — no history, counters, or clocks. `commitOutcome` compares the text a retry renders against the text an earlier commit stored, so a codec that consulted a counter would misclassify a worker's honest retry. Determinism is not idempotence: `serialize` still need not map its own decoded output back to the text it came from.
- A codec's output is neither cloned nor frozen. `structuredClone` would reject an outcome type that is codec-serializable but not structured-cloneable (a `URL`), and `Object.freeze` throws outright for one that is not freezable (a non-empty `Uint8Array`) — both of which the codec contract allows. Immutability comes from the durable text instead: a realization stores the text and decodes it afresh on every read.
- Every committed outcome a realization reads out of storage passes `parse` before it decides anything, including on the branch that answers `conflict`. A stored text the codec rejects is broken durable state and now throws instead of being reported as an ordinary caller conflict. Outcomes are decoded per read rather than handed out as one shared instance, so a caller that mutates a value whose interior `Object.freeze` cannot reach — a `URL`, say — changes nothing a later read reports. `InMemoryAttemptRepositoryState.committedOutcomes` is therefore `Map<string, string>` of durable texts, the in-memory counterpart of the stored column, instead of `Map<string, DurableOutcome<TOutcome>>` — and `InMemoryAttemptRepositoryState` loses its type parameter, since none of its maps carries an outcome-typed value any more.
- `createInMemoryAttemptRepository(codec, seed?)` and `createSqliteAttemptRepository(db, codec)` require an `OutcomeCodec`; `workflowRunResultOutcomeCodec` is exported from the testing entry for the workflow adapter.
- `runAuthorityDispatchedAttempt` returns the committed `TOutcome`; the `{ state: 'authority-committed', result }` completion wrapper is built by the Worker dispatch runner and the runtime-node `WorkerRunner`.
- Every bare `ExecutionAttemptRepository` / `ExecutionAttemptAuthority` reference is a compile error until it names its outcome type.
