A stop of an owned process or tree is now one in-flight operation per owner, and every way of completing it joins that operation. Observation windows that measure how a process answers the forceful stage start only after the bounded termination has finished, and nothing waits for an end that nobody requested.

- `@makaio/subprocess`, Windows tree stop: the wait for the exit after the `taskkill` of a stop starts once `taskkill` has finished, instead of running beside it. A slow `taskkill` no longer uses up the observation window and gets the exit classified as `unobserved` the moment it returns; only the caller's deadline ends a stop while its termination is still running. A child that exits by itself while `taskkill` is still ending its descendants no longer ends the transport early: the end report waits for `taskkill` (bounded by the exit observation time and by a `close({ deadline })`) and reports a refused termination as `tree: unproven (signal-error)` and an unfinished one as `tree: unproven (poll-timeout)`, so a restart is withheld for descendants that may still run. A `taskkill` that succeeded for the whole tree counts as the proof (`quiescent`); see `subprocess-windows-no-proof-no-restart`. The ordering is tested on POSIX hosts through the stop's injectable platform and `taskkill` seam; the transport's own Windows wiring runs only on a Windows host, where no CI job exists yet.
- `StdioServerTransport.disconnect()`: a second call while the first is still pending, and a call that finds no current session, now wait for every session whose end has not been reported, instead of resolving at once while the child and its tree may still run. A `disconnect()` that leaves a process running is logged once per session.
- Codex app-server connector: `close()` and `abort()` request the end of the transport the connector holds, whether or not a JSON-RPC client exists or is built on it. Before, a connector given a `transport` that closed before its first connection, or that was given an injected client as well, waited forever for an end nobody requested. The request is idempotent and is also made when closing the client throws.
- Native probe driver (`runCommand`): once the hard deadline started a tree termination, the run ends only after it has finished, also when the provider exits by itself meanwhile, so the caller no longer removes the workspace while descendants may still write to it. A termination that fails fails the run, instead of being discarded behind the child's own exit.
