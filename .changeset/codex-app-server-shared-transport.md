"@makaio/adapter-codex-app-server": major
"@makaio/ai-adapters-core": minor

The codex app-server adapter runs its child on the shared JSONL transport from `@makaio/subprocess` instead of spawning and supervising it itself. `createStdioTransport` is now a factory over `createJsonlTransport` with the app-server's options: the environment replaces the host environment instead of extending it, stderr is suppressed with one content-free warning, a throwing message consumer fails the channel and stops the child, stdout ending without an exit is terminal, an unterminated final line is parsed at the genuine end of stdout, and the app-server stays a direct child of the host (`terminateTree: false`).

The connector evaluates the end report (`ended`) of each app-server generation exactly once. A requested end of the generation that still answers for the connector finalises its turn locally; an unexpected end or a failed spawn is a terminal connector error, described by codes and signals only. A generation that a reset already replaced finalises nothing, so its end no longer reaches the generation or the turn that replaced it. Because the cause is derived from the order of what the transport observed, a close issued while an unexpected end is being delivered no longer causes a second finalisation. The connector derives the stop timing from its exit observation budget (`APP_SERVER_STOP_TIMING`: kill grace, exit observation and drain together stay below `CONNECTOR_EXIT_OBSERVATION_MS`), so a child that ignores `SIGTERM` is killed and observed inside the budget. Generation retirement and the shutdown report consume `exitObserved`, which fulfils on an observed exit only. `close()` resolves only after the transport's end report was delivered, so the requested end has been finalised (the interrupted turn completed) when it returns; the exit observation still alone decides the reported class.

In `@makaio/ai-adapters-core`, the evidence consumers `exitWasObserved`, `reportObservedExit` and `GenerationRetirementLedger.supersede` accept an `ExitObservation`: a promise whose declared fulfilment type can describe an unobserved end, such as a transport's end report, is refused at compile time. The check reads the declared type only, so a promise widened to `Promise<unknown>` or mapped away from an end report still passes; callers pass the observation promise itself. `GenerationRetirementLedger.retire()` keeps watching after its budget expired, as `abandon()` already did, so a generation whose end is observed late leaves the ledger and stops capping later teardown reports.

**Breaking (`@makaio/adapter-codex-app-server`):**

- `createStdioTransport(cwd, env, binaryPath?)` is now `createStdioTransport({ cwd, env, binaryPath?, timing? })` and returns an `IJsonlTransport`. `timing` defaults to the exported `APP_SERVER_STOP_TIMING`, the connector's budget-derived stop timing. The adapter's own `StdioTransport` type, its `exited` promise and `shutdownRequested()` are removed; use `ended`, `exitObserved` and `status`. `close()` is the transport's bounded, asynchronous close. The `StdioMessage` type is removed with it.
- `createJsonRpcClient(transport, onTransportFailure?)` is now `createJsonRpcClient(channel)`: the owner callback is gone, because the connector reads the transport's end report instead.
- The `transport` connector option takes an `IJsonlTransport`; the connector evaluates its end once, like that of a transport it spawned. An injected transport is single-use: the connector cannot replace it, so a failed handshake on it closes it and terminates the connector.
- A throwing message consumer now ends the transport and stops the child instead of being reported while the child keeps running. Error messages read `codex app-server ended unexpectedly: exited with code N` (or `failed to start: could not be spawned (ENOENT)`) instead of `codex app-server exited with code N`; a requested end reads `codex app-server stopped on request: …`, with the same process name.
