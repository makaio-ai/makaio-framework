A malformed stdout line from a JSONL subprocess no longer ends unrelated work. The `IJsonlTransport` error channel now carries only the end of the transport, reported once and after the last stdout message: a child that could not be spawned, any exit `close()` did not request (including exit code `0`), or a signal the transport did not send itself (clean and signal exits were previously not reported at all, so pending JSON-RPC requests waited for their timeout, or forever without one). Malformed lines are dropped and logged as a count, never with their content.

- `createJsonRpcClient` keeps pending requests correlated across malformed lines. A transport failure now closes the client like `close()`: pending requests reject with the transport error and later requests reject immediately instead of being written to a dead process. An error response whose `error` member is not an object rejects its request instead of throwing inside message dispatch.
- `createJsonlTransport` isolates listeners: a throwing message or error listener is logged and no longer escapes as an uncaught exception or skips later listeners. Each dispatch reaches every listener registered when it started, even when an earlier listener calls `close()`. The shared `notifyListeners` helper is exported for transports with the same dispatch contract.
- The codex app-server transport no longer fails the connector on a malformed stdout line; it logs `[codex app-server] dropped N malformed JSONL line(s)`. Every app-server exit that `close()` did not request, including exit code `0`, is now a transport failure (`codex app-server exited with code 0`); a clean exit was previously ignored, leaving the connector bound to a dead process. A transport failure now reaches both the JSON-RPC client and the connector, so in-flight requests reject with the failure instead of `JSON-RPC client closed`. `createJsonRpcClient(transport, onTransportFailure)` takes the owner's failure callback, which runs after the client has settled its requests and is unsubscribed on the first failure or when the client closes, so a transport reused across reconnects notifies only the current client's owner.

**Breaking:**

- `StdioServerTransport` no longer terminates a session when the child writes a malformed stdout line. A child that writes non-protocol text (a banner, help output, a wrong binary) and then exits still rejects `ready` through the exit; a child that keeps running without ever sending `subscribe-sync-complete` leaves `ready` pending, as a silent child already did. A session now ends on the JSONL transport's end instead of the raw process `exit`, so a response the child wrote before exiting still settles its correlation; the termination error reads `<processName> exited with code N` (or `signal S`) instead of `Child process exited (code N) before subscribe-sync handshake completed`. `send()` rejects with `StdioServerTransport: not connected` from the observed child exit onwards, even while a descendant holding stdout keeps the session open, instead of tracking a correlation whose message was never delivered; stdout keeps draining for requests already pending.
- The codex app-server `StdioTransport` is multi-subscriber: `onMessage` and `onError` add a subscription and return its unsubscribe function instead of replacing the previous callback.
- `JsonlDecodeResult.errors` and `DecodeBusChunkResult.errors` (raw unparseable lines) are replaced by `malformedLineCount: number`, so raw line content never leaves the decoder. `StdioClientTransport` reports `Failed to parse N stdio JSONL line(s)` instead of echoing the line.
